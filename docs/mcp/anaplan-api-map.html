Decisions so far

  1. Endpoint I/O comes from the wiki's transactional pages, not the reference site, whose response examples are mostly illustrative.
  2. Financial Consolidation endpoints are out: a separate product with separate auth.
  3. v1 is read-only against Anaplan. Writes and state changes stay on the map, dashed.
  4. Intent-level tools that take names. No generic URL tool; no hand-built URLs.
  5. All seven workflows are in v1, bulk extract included.
  6. One server for all customers. Each call resolves the model through the registry; unregistered models are refused. Tokens live in memory per auth profile.
  7. list_models shows unregistered models too. register_model writes models.py and registry.md together; engine is supplied, never guessed. New customers stay with project-setup.
  8. Fetched data is never stored. Values live in server RAM for the session and reach the agent only as a filtered sample with coordinates.
  9. read_cells tries the transactional read first, then falls back to a streamed bulk read: filter while streaming, stop early, cache in RAM only when the view is small enough, always delete the read request.
  10. Row and column positions mean the view's grid as Anaplan shows it, 1-based, after page selection. Every returned cell echoes its coordinates.
